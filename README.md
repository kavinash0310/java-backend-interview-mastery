# Java Backend Interview Mastery

A structured, practical question bank for learning Java backend development and preparing for interviews. Topics range from Core Java and Spring Boot to databases, distributed systems, production support, system design, and complete backend projects.

## How to use this repository

Start with the learning path below, choose a module, and open its beginner Q&A supplement. Use the module's deeper answer pages and linked references when you want more detail.

> **Repository status:** Every course module now reaches at least 30 distinct questions across its beginner Q&A supplement and existing deep-dive answers. The quick pages use plain language, examples where useful, and primary references.

## Question format

Each answer uses the sections that help explain it. Related prompts share a canonical answer when they ask the same thing; scenario indexes link to that answer instead of repeating it.

```markdown
# Question

## Short Interview Answer
## Simple Explanation
## Easy Way to Remember
## How It Works Internally
## Example or Code Example
## Real-World Use Case
## Common Mistakes
## Interview Follow-Up Questions
## Quick Revision
```

Explain important code lines and expected output when useful. Mention version-specific behavior where it matters. Prefer practical trade-offs over one-size-fits-all claims.

## Duplicate-checking and contribution guidelines

Before adding a question:

1. Search existing pages for exact wording and similar meaning.
2. Compare the intent and scope; label a match as exact duplicate, semantic duplicate, related but distinct, or new.
3. Improve an existing answer when the question is already covered. Create a separate page only for a genuinely different concept.
4. Check all questions in the same batch against one another.
5. Use a descriptive lowercase kebab-case filename in the matching subtopic, or use a module-level `interview-questions.md` for a closely related set.
6. Add the new page to that module's **Question index** and link related pages rather than copying content.
7. Check internal links, code formatting, accuracy, and the final diff before committing.

Example path: `core-java/collections/hashmap-internals.md`.

## Repository structure

- `README.md` — course overview, module index, learning path, and contribution workflow.
- `<module>/README.md` — module description, subtopic links, learning outcomes, and question index.
- `<module>/<subtopic>/<question>.md` — a focused answer page.
- `<module>/interview-questions.md` — one guide for a closely related set of questions.

Each module guide links to a beginner Q&A supplement and the existing deeper answers. Improve an existing answer when a new prompt asks the same thing.
