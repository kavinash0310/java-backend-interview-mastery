# Java Backend and Frontend Interview Mastery

A structured, practical question bank for Java backend and frontend interview preparation. The backend path covers Core Java, Spring Boot, data, messaging, distributed systems, production support, and system design. The frontend path adds HTML, CSS, JavaScript, TypeScript, Angular, RxJS, and frontend testing.

## How to use this repository

Start with the learning path below, choose a backend or frontend module, and open its easy, medium, hard, or tricky Q&A set. Use each module guide to navigate its subtopics and official references.

> **Repository status:** The 24 Java backend modules have 40 easy, medium, and hard questions and 30 tricky questions each. The 7 frontend modules have 40 questions at every level. Sets use numbered answers, examples or code where useful, and references.

## Beginner-to-advanced learning path

### Phase 1 — Foundations

Learn the Java language and problem-solving basics, then understand concurrency and the JVM.

- [Core Java](core-java/README.md)
- [Data Structures and Algorithms](data-structures-algorithms/README.md)
- [Online Assessment Practice](online-assessments/README.md)
- [Multithreading and Concurrency](multithreading-concurrency/README.md)
- [JVM and Memory Management](jvm-memory-management/README.md)

### Phase 2 — Build web services

Learn Spring, build HTTP APIs, and secure them.

- [Spring Framework](spring-framework/README.md)
- [Spring Boot](spring-boot/README.md)
- [REST APIs and HTTP](rest-apis-http/README.md)
- [Spring Security](spring-security/README.md)

### Phase 3 — Data and messaging

Work with relational persistence, caching, and asynchronous event flows.

- [SQL and Relational Databases](sql-relational-databases/README.md)
- [JDBC, JPA and Hibernate](jdbc-jpa-hibernate/README.md)
- [Redis and Caching](redis-caching/README.md)
- [Apache Kafka and Messaging](kafka-messaging/README.md)

### Phase 4 — Production engineering

Improve design, testing, delivery, deployment, and observability.

- [Design Patterns and Clean Code](design-patterns-clean-code/README.md)
- [Testing](testing/README.md)
- [Maven, Gradle, Git and GitHub](build-tools-version-control/README.md)
- [Docker, Kubernetes and CI/CD](docker-kubernetes-cicd/README.md)
- [Cloud and AWS](cloud-aws/README.md)
- [Logging, Monitoring and Observability](logging-monitoring-observability/README.md)

### Phase 5 — Architecture and practice

Connect service architecture to system design, operational scenarios, and end-to-end projects.

- [Microservices Architecture](microservices-architecture/README.md)
- [System Design and Architecture](system-design-architecture/README.md)
- [Scenario-Based Interview Questions](scenario-based-interview-questions/README.md)
- [Real-World Backend Projects](real-world-backend-projects/README.md)
- [HR and Managerial Interviews](hr-managerial-interviews/README.md)

### Phase 6 — Frontend application development

Learn the browser foundations first, then build typed, reactive Angular interfaces and test them.

- [HTML and Web Accessibility](html-accessibility/README.md)
- [CSS, Layout, and Responsive Design](css-responsive-design/README.md)
- [JavaScript and Browser Fundamentals](javascript-browser/README.md)
- [TypeScript](typescript-language/README.md)
- [Angular](angular/README.md)
- [RxJS and Reactive Programming](rxjs-reactive-programming/README.md)
- [Angular and Frontend Testing](angular-testing/README.md)

## Question format

Each answer uses the sections that help explain it. Related prompts share a canonical answer when they ask the same thing; scenario indexes link to that answer instead of repeating it.

```markdown
# Question

## Short Interview Answer
## Simple Explanation
## Easy Way to Remember
## How It Works Internally
## Example or Code Example
## Real-World Use Case
## Common Mistakes
## Interview Follow-Up Questions
## Quick Revision
```

Explain important code lines and expected output when useful. Mention version-specific behavior where it matters. Prefer practical trade-offs over one-size-fits-all claims.

## Duplicate-checking and contribution guidelines

Before adding a question:

1. Search existing pages for exact wording and similar meaning.
2. Compare the intent and scope; label a match as exact duplicate, semantic duplicate, related but distinct, or new.
3. Improve an existing answer when the question is already covered. Create a separate page only for a genuinely different concept.
4. Check all questions in the same batch against one another.
5. Use a descriptive lowercase kebab-case filename in the matching subtopic, or use a module-level `interview-questions.md` for a closely related set.
6. Add the new page to that module's **Question index** and link related pages rather than copying content.
7. Check internal links, code formatting, accuracy, and the final diff before committing.

Example path: `core-java/collections/hashmap-internals.md`.

## Repository structure

- `README.md` — course overview, module index, learning path, and contribution workflow.
- `<module>/README.md` — module description, subtopic links, learning outcomes, and question index.
- `<module>/<level>-interview-questions.md` — numbered Q&A sets. Backend modules have 40 easy, medium, and hard questions plus 30 tricky questions; frontend modules have 40 at each level.
- `<module>/<subtopic>/<question>.md` — a focused answer page.
- `<module>/interview-questions.md` — one guide for a closely related set of questions.

Backend guides link to 40-question easy, medium, and hard sets and a 30-question tricky set. Frontend guides link to 40-question sets at all four levels. Improve an existing answer when a new prompt asks the same thing.
