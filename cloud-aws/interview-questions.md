# Cloud and AWS Interview Questions

## An EC2 instance needs secure access to S3. How do you avoid stored credentials?

Give the workload an IAM role and let the AWS SDK use its temporary credentials: an EC2 instance profile, an ECS task role, an EKS workload identity such as EKS Pod Identity/IRSA, or the `jobRoleArn` on an AWS Batch job definition. For AWS Batch, distinguish that application role from `executionRoleArn`, which is for the container/Fargate agent. Grant only the required S3 actions on the required bucket or prefix, and keep credential refresh with the SDK provider chain. Avoid static keys in job parameters, environment files, images, or logs; review the role trust policy, permission scope, data encryption, and audit trail. See [AWS Batch job roles](https://docs.aws.amazon.com/batch/latest/userguide/job_definition_parameters.html), [AWS Batch execution roles](https://docs.aws.amazon.com/batch/latest/userguide/execution-IAM-role.html), the [AWS SDK for Java credential chain](https://docs.aws.amazon.com/sdk-for-java/latest/developer-guide/credentials-chain.html), [ECS task roles](https://docs.aws.amazon.com/AmazonECS/latest/developerguide/task-iam-roles.html), and [EKS workload identity](https://docs.aws.amazon.com/eks/latest/userguide/service-accounts.html).
